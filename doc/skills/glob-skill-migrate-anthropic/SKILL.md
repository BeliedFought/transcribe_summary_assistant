# Миграция навыка на формат Anthropic Agent Skills

Переносит навык из внутреннего формата пакета (плоский файл `doc/skills/`) в формат Anthropic Agent Skills (каталог с `SKILL.md`). Результат - новый каталог навыка в каталоге навыков целевого инструмента и строка в индексе навыков. Исходный навык и все существующие файлы не изменяются.

## Когда использовать

- Пользователь просит мигрировать, конвертировать или перенести навык в формат SKILL.md / Anthropic / opencode
- Пользователь явно указал исходный навык: тег `@doc/skills/<file>`, имя файла или `id`
- Репозиторий переводит навыки на `doc/standards/skill_anthropic_standards.md`

Без явно указанного исходного навыка не применять: запросить у пользователя путь или имя, кандидатов не подбирать самостоятельно.

## Инструкция

### 0. Предусловия

- Исходный навык указан пользователем явно. При отсутствии - спросить и ждать ответа.
- Прочитать оба стандарта: `doc/standards/skill_anthropic_standards.md` (целевой формат), `doc/standards/skill_standards.md` (исходный формат).
- Целевой каталог - подпапка `doc/skills/<kebab-id>/` с `SKILL.md` в корне (раздел 3 стандарта). Боевые каталоги инструментов (`.opencode/skills/` и др.) не использовать: деплой - отдельный процесс, стандартом не регламентируется.
- Имя целевого каталога свободно. Занято - стоп, уточнить у пользователя.

### 1. Изучить исходный навык

1. Прочитать файл навыка целиком.
2. Извлечь frontmatter: `id`, `description`, `auto_apply`, `version`, `status`.
3. Зафиксировать состав и порядок разделов (Описание, Когда использовать, Предусловия, Инструкция, Критерии завершения, Примеры, Ограничения и др.).
4. Определить деструктивность: операции удаления, перезаписи, миграций БД, деплоя - по разделу «Ограничения» и командам инструкции.
5. Оценить объем: если тело исходника больше ~500 строк - заранее спланировать вынос материала в `reference.md` / `examples.md`.

### 2. Инвентаризация ссылок и кода

Пройти по телу исходника и собрать все внешние сущности. Для каждой - проверить существование пути и назначить судьбу:

| Категория | Что искать | Судьба при миграции |
| --------- | ---------- | ------------------- |
| Ссылки на файлы проекта | `../../src/<path>`, `run/`, `data/`, `sql/`, `doc/specs/`, `output/` | Переписать от корня репозитория; контракт (назначение, формат, режимы) - в `reference.md` |
| Команды вызова | `python -m src.tools.<module>`, bash-блоки вызова модулей | Перенести в `## Инструкция` как есть |
| Встроенный код | fenced-блоки кода в теле | Короткие (до ~30 строк) оставить в теле; длинные и переиспользуемые - в `scripts/<name>.<ext>` с вызовом из тела |
| Внешние URL | интернет-источники, API | Оставить в теле, если участвуют в инструкции; справочные - в `reference.md` |
| Шаблоны и примеры файлов | заготовки артефактов | `templates/` или `examples.md` |

Битые пути - зафиксировать для отчета, молча не выбрасывать и не «чинить».

### 3. Сформировать пакет

Имя каталога - `id` исходника в kebab-case: `db_migrate` -> `db-migrate`, `go_cli` -> `go-cli`.

Frontmatter - только ключи спецификации:

```yaml
---
name: <kebab-id>
description: <WHAT + WHEN, до 1024 символов; из description исходника, при необходимости дополнить триггерами из «Когда использовать»>
metadata:
  version: <version исходника или 1.0.0>
  status: <status исходника или stable>
---
```

Отображение полей исходника:

| Исходник | Цель |
| -------- | ---- |
| `id` | `name` (snake_case -> kebab-case) |
| `description` | `description` (проверить наличие WHAT и WHEN) |
| `auto_apply: true` | не переносится; авто-применение по `description` - поведение по умолчанию |
| `auto_apply: false` | правило «только явный вызов по имени» - в тело; для Claude Code допускается `disable-model-invocation: true` (расширение, раздел 5 стандарта) - только если навык не распространяется по строгой спецификации |
| `version`, `status` | `metadata.version`, `metadata.status` |

Отображение разделов:

| Исходник | Цель |
| -------- | ---- |
| Заголовок H1 | Заголовок H1 |
| Примечание-цитата | абзац после заголовка или в `## Ограничения` |
| Описание | вводный абзац до `## Когда использовать` |
| Когда использовать | `## Когда использовать` |
| Предусловия | первый подраздел `## Инструкция` (Предусловия) |
| Инструкция | `## Инструкция` |
| Критерии завершения | `## Критерии завершения` |
| Примеры | `## Примеры` |
| Ограничения | `## Ограничения` |
| Скрипт, Пример результата | вызов `scripts/`, `examples.md` |
| Ссылки на стандарты и соседние навыки | `## Ссылки` |

Требования к телу - по разделу 8 `skill_anthropic_standards.md`:

- императив, до 500 строк; излишки - в `reference.md` / `examples.md` с условиями чтения;
- переносить полный текст разделов, включая вводный текст между заголовком раздела и первым подразделом; молча не выбрасывать ничего;
- при миграции нескольких навыков в одной сессии ссылки на уже мигрированные навыки обновлять на новые имена (`id` snake_case -> `name` kebab-case); перечень переименований - в отчет;
- если инструкция навыка при последующем применении удалит результат миграции (например, пересборка индекса не учитывает новые каталоги `SKILL.md`) - минимально скорректировать формулировку и зафиксировать адаптацию в отчете;
- пути к файлам проекта - от корня репозитория: исходник лежал глубже (обычно в `doc/skills/<repo-name>/`), старые относительные пути `../../` из нового каталога нерабочие;
- вызов скриптов пакета - через переменную каталога навыка (`${CLAUDE_SKILL_DIR}` или аналог инструмента);
- язык тела - язык исходного навыка (как правило русский); перевод на английский - только по запросу пользователя.

### 4. Проверить пакет

Прогнать чеклист автора из раздела 15 стандарта `skill_anthropic_standards.md`. Дополнительно:

- [ ] в frontmatter нет `id` / `auto_apply` и других полей внутреннего формата
- [ ] `name` совпадает с именем каталога, kebab-case, до 64 символов
- [ ] `description` - WHAT + WHEN, до 1024 символов
- [ ] тело до 500 строк
- [ ] скрипты исполняемые (`chmod +x`), с shebang
- [ ] все пути из инвентаризации существуют; битые - перечислены в отчете
- [ ] относительные пути `../..` из исходника переписаны от корня репозитория
- [ ] разделы перенесены полностью (текстовое сравнение с исходником): «Когда использовать», «Инструкция» с вводным текстом, «Критерии завершения», «Примеры», «Ограничения»
- [ ] адаптации сверх механического переноса (переименования ссылок на мигрированные навыки, скорректированные формулировки) собраны для отчета
- [ ] после `py_compile` скриптов артефакты `__pycache__` удалены

### 5. Зарегистрировать в индексе навыков

- Производный репозиторий: добавить строку в `_index_skills_repo.md` в раздел навыков формата SKILL.md (создать раздел, если отсутствует): колонки «Навык, Путь, Назначение».
- Хаб: добавить строку в `_index_skills_hub.md` в раздел «Навыки формата Anthropic Agent Skills (SKILL.md)».
- Полную пересборку индексов (`glob_update_indexes` / `hub_sync_indexes`) не запускать без запроса: они собирают индекс из `doc/skills/` и могут не знать о разделе SKILL.md. После любого их прогона проверить, что строка сохранилась, при утере - восстановить.

### 6. Ничего существующего не менять

- Исходный навык в `doc/skills/` остается как есть и продолжает работать.
- Не править стандарты, код проекта, файлы, на которые ссылается навык, конфигурацию инструментов.
- Разрешенные записи: новые файлы нового каталога и одна строка регистрации в индексе навыков.
- Подтвердить через `git status`: только новый каталог (untracked) и одна измененная строка индекса. Любие другие изменения - откатить и повторить шаг аккуратнее.

### 7. Отчет пользователю

- Дерево созданного пакета.
- Таблица соответствия: поле или раздел исходника - куда перенесен.
- Судьба каждой ссылки и блока кода из инвентаризации.
- Адаптации сверх механического переноса: переименования ссылок на мигрированные навыки, скорректированные формулировки - с обоснованием каждой.
- Битые ссылки, превышения лимита объема, открытые вопросы - отдельным списком.
- Напоминание: навык хранится в `doc/skills/<kebab-id>/`; чтобы инструмент начал его применять - скопировать каталог в боевой каталог инструмента (например `.opencode/skills/`) отдельной операцией, после деплоя вызов по имени `name`.

## Примеры

1. «мигрируй @doc/skills/report_generator/deploy_run.md на формат SKILL» -> изучить навык; инвентаризация: модули `src/`, команды, пути отчетов; создать `doc/skills/deploy-run/SKILL.md`, пути переписать от корня репозитория; зарегистрировать в индексе; отчет; исходник не тронут.
2. «перенеси genre_wiki_fill в opencode» -> пакет `doc/skills/genre-wiki-fill/`, встроенный код вынести в `scripts/`, описание на основе description и «Когда использовать» исходника; деплой в `.opencode/skills/` - отдельно, не в рамках миграции.

## Ссылки

- `doc/standards/skill_anthropic_standards.md` - целевой формат: frontmatter, структура тела, progressive disclosure, чеклист автора
- `doc/standards/skill_standards.md` - исходный формат: поля frontmatter и состав разделов
- Индекс навыков репозитория (`_index_skills_repo.md`; в хабе - `_index_skills_hub.md`) - регистрация результата

## Ограничения

- Миграция - только создание нового пакета; удаление исходника и обратная конверсия не выполняются.
- Распространение в другие репозитории - навыком `hub_sync_skills` для общих навыков (каталоги с префиксом `glob-`); без префикса навык проект-специфичен и агрегируется в хаб под `doc/skills/ext/<repo-name>/<name>/`.
- Мигрируется один навык за запуск; для пакета навыков - повторять по каждому, указанному пользователем.
